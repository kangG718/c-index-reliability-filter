1) 재현성 문제는 십중팔구 random seed 고정 문제입니다. 결과가 실행할 때마다 달라진다는 건 모델 예측력과는 별개의 문제로 보통 인식이 됩니다. RF, GBM, MLP 전부 학습 과정에 stochastic 요소가 있으니까 numpy, random, sklearn(또는 사용하고 있는 프레임워크) 전부 seed를 명시적으로 고정해주셔야 하고, train/test split도 마찬가지로 말씀 드릴 수 있겠습니다. 이거 안 잡으면 어떤 결과를 내놔도 신뢰할 수가 없어서, feature 설계보다 이게 먼저라고 봐 주시면 되겠습니다. 코드 상단에 seed 고정하는 함수 하나 만들어서 일괄 관리하는 게 좋습니다.
2) Sharpe ratio 값이 비정상적으로 큽니다. Best Scenarios 표를 보면 MLP에서 Sharpe가 36.69, GBM에서 10.69가 나오는데, 현실적으로 이 수치는 말이 안 돼요. 평가 구간이 너무 짧아서 annualize할 때 뻥튀기되는 건지, 아니면 수익률 계산에 look-ahead bias가 들어간 건지, 거래비용 반영 전후 차이인지 확인해봐야 합니다. 계산 로직을 한번 꼼꼼히 점검해 주시면 좋을 것 같습니다. 만약 아니라면 좋은 게 맞는데, 뭔가 중간에 문제가 있을 가능성이 높습니다.
3) Disagreement rate가 전 모델에서 Top-3 기준 80~86%로 매우 높게 나오는 건 그 자체로는 좋은 시사점이라고 생각합니다만, 이게 재현 가능한 수치인지가 지금은 불확실하니까 seed 고정 후에 다시 확인해야 의미가 있습니다. 재현 확인되면 이 높은 disagreement가 왜 발생하는지(모델 구조적 차이인지, feature 간 다중공선성 때문인지) 분석하는 게 논문 contribution이 될 수 있으니 그때 같이 논의해 보면 좋을 것 같습니다.
4) Robustness 표에서 MDD_Improved가 세 모델 전부 0입니다. 필터링이 Sharpe 개선에는 일부 기여하지만 drawdown 방어에는 전혀 기여하지 못한다는 건데, 이 결과를 어떻게 해석할 건지 한 번 생각해 보시면 좋을 것 같습니다. 필터링 기준 자체를 재설계해야 하는 건지, 아니면 이것도 하나의 발견으로 논문에 서술할 건지 약간 스탠스를 정하긴 해야할 것 같습니다. Drawdown 반영이 아예 다 0이 정확하게 나오기도 쉽지 않을 수가 있는데 코드 오류가 없는지 한 번 보면 좋을 것 같습니다.
5) Feature 설계 강화는 위의 1-2번을 해결 하시고 진행하시는게 좋지 않을까 합니다. 기반이 안 잡힌 상태에서 feature를 아무리 바꿔봐야 결과가 매번 달라지면 어떤 feature가 실제로 효과가 있는지 판단 자체가 불가능합니다.
일단 시험 잘 마무리하시고, 시험 끝나시면 seed 고정 → Sharpe 계산 검증 → 재실행 이 순서로 진행해 보시면 좋지 않을까 합니다.
